## Contract and persistence

- `src/app/inputActions.ts` owns stable IDs `settings.open`, `navigation.back`, `navigation.forward`, `modal.dismiss`. Resolution is modal > focused > route > global with a modal barrier and one winner. Unavailable consumers fail safely; text editing and IME input suppress shortcuts. Consumers own action availability and execution; the registry cannot authorize campaign actions.
- Supported profiles are physical US-position keyboard keys (KeyboardEvent.code) (Alt+Shift plus letters/numbers/arrows), standard-mapped Gamepad buttons 0–16, and native button activation for pointer/touch/assistive input. Tab/Enter/Space/Escape and browser-command/AltGraph chords are reserved. OS-intercepted shortcuts may not reach the browser; native controls remain available. Multiple keyboard/controller bindings are representable (at most four per action); the editor replaces or clears each device's binding. Conflicts across actions are rejected, not silently reassigned.
- `src/app/inputRuntime.ts` is the shared application preference/runtime owner. Key `containment-protocol-input-preferences`, schema `{version:1,overrides}` stores only bounded binding overrides, separately from campaign storage. No existing application preference store was present; Academy must reuse this path. Missing entries inherit current authored defaults; explicit empty arrays remain cleared. Removed IDs are discarded; future renamed IDs require an explicit version migration, never label guessing. Unknown versions, malformed records and conflicts fall back to defaults. Failed writes retain session controls with a visible warning. Reset restores all authored defaults. Preferences load once per page; cross-tab live synchronization is outside this boundary.
- `resolveInputBindingLabel` has the existing tutorial binding-resolver shape and exposes actual current labels without giving tutorial code command authority. Pointer/touch labels identify native controls. No second tutorial registry.
- Runtime registration follows component lifetimes. Controller polling sleeps without devices, considers at most four standard controllers and 17 buttons each, ignores unsupported mappings and unavailable APIs, and uses fresh API snapshots. Held input, newly connected input and focus-return input must release before firing. One edge batch cannot dismiss a modal and fire an underlying navigation command. No axes, device IDs or telemetry.

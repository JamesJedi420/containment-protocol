## Goal

One authored procedure context iterates the frozen `VOLATILE_ACTION_V1_PHASE_IDS` spine as repeated phase slices. `volatile_action_procedure_v1` remains a declared variant tag. Iteration is authored. Frozen phase ids stay the same length and order. SPE-2916 explanation stays always emitted and gains stable iteration reason codes. No second sequencer, parallel timer, or forked phase ids. Do not close parent SPE-62 or GitHub #62.

This child owns the remaining parent AC: long rituals or engineering tasks iterate phase slices on the shared spine rather than spawning unrelated parallel timers.

## Boundary

Extend `resolveVolatileActionPhasePipeline` in place. Prefer existing domain helpers over new abstractions. Do not invent a second sequencer, a parallel timer, forked phase ids, or a persisted iteration ledger. Pipeline stays GameState-free. This child does not own hydrate.

Frozen shared phase order: `posture_commit` → `environmental_read` → `clash_window` → `effect_emission` → `cleanup`. Do not add, remove, or reorder inspectable ids. Do not silently fork phase ids.

`iteration` is an optional tagged union on the input. Never infer iteration from SPE-54 scores, actor array order, phase array order, variant, or mode. Omit or `{ kind: 'none' }` keeps the SPE-2930 default. `{ kind: 'present' }` requires `authority: 'authored_procedure'` plus a `procedureId`.

Present iteration resolves **one extra slice pass** on the same five ids. Inspectable `phases` stay length 5. Extra-pass records reuse those ids and already-resolved statuses after no-stakes / interrupt / hold / wiring precedence. Iteration does not revive skipped clash/emission.

Fail-closed: object required when iteration is present; `kind` must be `none` | `present`; missing/unknown authority, empty/unsafe `procedureId`. Match existing throw-string style.

SPE-2916 `explanation` is still always emitted. Iteration reasons are stable string codes derived from already-resolved iteration records. No second authored ledger.

Optional hidden-combat attach may include iteration without changing outcome math and without starting new combat systems.

Do not change the SPE-54 kernel, SPE-2915 hazard grammar, SPE-2902 hold persistence, SPE-2916 always-emitted explanation contract, or SPE-2930 wiring grammar. Equal SPE-54 scores keep fallback then actor id. Do not implement SPE-73 odds/outcomes, SPE-2847 orchestration, SPE-2217 field action economy, or SPE-40 mission tradeoffs.

## Acceptance

- Explicit iteration present vs omit / `{ kind: 'none' }` is inspectable; omit and none are byte-stable equals
- Present tagged snapshot iterates one extra slice pass on the same five frozen ids; inspectable `phases` stay length 5 in frozen order
- Iteration is never inferred from variant, mode, SPE-54 scores, or array order; `volatile_action_procedure_v1` without authored iteration stays a tag only
- Iteration does not revive no-stakes skipped clash/emission; interrupt rewrite, hold, and SPE-2930 wiring still win over iteration when those statuses already apply
- SPE-2916 explanation is still always present; iteration reasons are stable string codes, not free-form prose
- Variant/mode tags unchanged across both SPE-2912 variants and all three modes
- Fail-closed unknown/missing iteration authority
- SPE-54 `volatileActionPriority` tests stay green
- Parent SPE-62 remains Backlog; do not close GitHub #62
